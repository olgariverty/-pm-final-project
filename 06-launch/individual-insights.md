# Individual Insights

## What changed

1. Returned to the assigned case persona, Lena, instead of using an unsupported persona.
2. Removed unsupported quantitative claims carried over from a different project.
3. Changed the experiment from immediate-versus-delayed availability to wallet provisioning versus no wallet provisioning during the test.
4. Kept M3 card retention as the primary metric and aligned its denominator with randomised activated cardholders.
5. Separated confirmed case inputs, synthetic planning signals, and proposed decision thresholds.
6. Removed assumptions about a specific platform, issuance timing, and card-delivery sequence.

## Aha moment

A feature is not strong because it sounds convenient; it is strong when the user friction, experiment exposure, primary metric, and business guardrail all describe the same causal bet.

## Key takeaway

Wallet provisioning can extend Riverty beyond partner checkout, but only a controlled test can show whether that access becomes durable usage without cannibalising Riverty's merchant-first channel.

## Decision requested

Approve a controlled friends-and-family beta subject to wallet-provider, Risk, and Compliance readiness. Scale only if M3 card retention improves and partner-checkout spend stays within the agreed boundary.
